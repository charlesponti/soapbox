The Misrouted Call

LLM tool misselection in production is a directory problem, not an intelligence problem — names, schemas, and a routing clerk beat a smarter operator

  • llm
  • tool-use
  • mcp
  • api-design
  • ai-engineering

A trace scrolls past on a terminal, and it reads like a wrong number. A request came in to create a Sweety Blinders collection and share it with Kelsey; the agent dialed create_place_list, the tool completed, the invite failed because the ID belonged to a different domain, and somewhere in the same log the model even dialed a tool called collection that was never on the board.

In a hotel, the switchboard operator routes by department name. Call for room service and the board sends you to the kitchen; call for a wake-up and it sends you to the front desk. That works until the hotel grows two departments that sound alike — Bells and Billing — and the operator is handed a directory with one line for each, a line that says nothing about which is which. Calls get through. They get through to the wrong floor, and the wrong floor answers in a friendly voice. Nothing crashes. The hotel just fills with politely misdelivered breakfasts.

LLM tool selection is that switchboard, and the model is the operator.

A Directory Problem

The failure is rarely a crash. Every tool was available and the model was GPT-4o class, and still the ambiguity resolved confidently and wrong: list_collections and list_place_lists read as near-synonyms, collection_id and place_list_id are both optional strings, so any ID looks valid. A description that says “Manage lists” gives the boundary nothing to lean on. Adapters strip namespaces — collections:create and places:create_list both flatten to create — and truncate descriptions to fit token limits. Past twenty visible tools, recall drops and the model stops reasoning about the contract and starts pattern-matching the most familiar-sounding name. The plausible wrong choice is the normal failure mode of tool selection.

No amount of model cleverness fixes a directory the model cannot read.

The Contract Fix

The library that outgrew its catalogers did not hire faster catalogers; it adopted Melvil Dewey’s decimal scheme, and any clerk who could read the numbers could find the book without ever having read it. A name that carries its own address is the oldest fix for a directory the operator cannot memorize.

Treat every tool definition like a public API contract. Name the tool for the domain object and the verb, so create_collection and create_place_list answer what they are without the description. Write the description as routing guidance — a when-to-use block, a when-not-to-use block, and a related line pointing at the sibling tool. In evaluations, one or two lines of “when not to use” cut misrouting between the collection and place-list domains by roughly sixty percent, a bigger lever than any prompt tweak in the same test.

Then make the schema refuse invention. collectionId is described as the UUID returned by create_collection, not a place-list ID; the invitee email is typed as an email; role is an enum that defaults to editor; and additionalProperties: false means a hallucinated argument fails fast instead of producing a silent no-op. Keep collection__create and place_list__create whole through the adapter instead of flattening both to create, and log both sides of any forced rename.

High-risk intents get a deterministic router instead of a guess. For a prompt like “share my list with Kelsey”, the agent checks for domain signals — collection, folder, set on one side, place, location, map on the other — and if both or neither fire, it asks which one you meant. The router either filters the visible tool set or forces a clarification turn. Correctness beats autonomy for share and mutate operations.

Two-Stage Routing

Even a perfect directory degrades once twenty or more tools are on the board, so stop showing all of them to one operator. The main agent holds three delegate tools and knows when to route; a domain subagent holds four to six tools and knows how to execute. Two-stage routing beats one flat choice over twenty. Skills carry the routing rules as injected system context at zero tool-slot cost, while MCP stays for live execution. The main agent never touches the domain tools; it only knows which expert to call.

Every turn now logs the decision trace: catalog version, the tools that were available, the selected tool, its arguments, the execution status, the model. That trace is the unit of debugging. Without it, “the tool ran but returned nothing” is unreproducible; with it, the choice can be replayed and measured.

The proof is the same forty prompts, run before and after the contract changes. With vague names and a flat adapter, the agent chose the correct tool 62 percent of the time and the correct arguments 41 percent. With distinct names, when-not-to-use lines, preserved namespaces, and strict schemas, it chose the correct tool 94 percent of the time and the correct arguments 88 percent. The delegate pattern closed the remaining six percent at the cost of one extra call — about a hundred and twenty milliseconds and 1.3 times the tokens. The original prompt now succeeds even when the descriptions overlap, because the wrong tool was never in the main agent’s list of options. No model change. Only interface design.

Smarter operators are expensive. They still misroute against a directory with one line per department, and they hand the wrong breakfast to the wrong guest with perfect confidence. The hotel does not need a smarter operator. It needs names that mean something, a routing clerk, and a log of every call.

The switchboard was never the problem.
